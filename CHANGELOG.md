## [1.0.0-canary] Unreleased

### Changed, 2026-08-23T04:41:26Z

- The delivery esteira was rewritten so that a deploy can no longer fail over configuration, under the director's order of this date. Every earlier failure of this esteira was a refusal over something the workflow could have resolved by itself, and each refusal cost him a manual step. Now exactly one secret is irreplaceable, `SERVER_SSH_KEY`, and preflight stops on it before the gate spends a minute, naming the one command that provides it. The host, the login, the deploy path and the public address resolve through a chain of repository secret, then repository variable, then a versioned default carried in the workflow, with the log naming the source of each and never printing a value; the four defaults are facts already published in `PREAMBLE.md` inside this same repository, so nothing new is disclosed. `REPO_DEPLOY_KEY` became optional, because a public repository is cloned anonymously over HTTPS and refusing over a key it does not need was the defect; the workflow detects the case, says which path it took, and fails with a named message only if a private repository is unreachable. `DOTENV_B64` became optional on a server that already carries its `.env`, which is kept with its variable count reported, and the deploy stops only when neither the secret nor a file exists, because configuration cannot be invented.
- The server is prepared instead of assumed on every run, each item a real incident that must never reach a person again: the application account is created when absent, the ownership of the deploy path is repaired, git is installed when missing, the Node runtime is raised to the engines floor of the manifest when below it, pm2 is installed when missing, and pm2 resurrection across a reboot is configured idempotently. Health is now proved twice with retries and deadlines, on the loopback interface where the deploy can blame itself and again on the public address through Cloudflare and nginx, and the deployed configuration is reported by coverage, how many documented names of `.env.example` are absent, by name and never by value.
- `scripts/bootstrap-repository.sh` brings a freshly created repository to the exact state the esteira expects in one idempotent command: description, homepage, nineteen topics, the four deployment-target secrets and the read-only deploy key when one has been minted, then a verification and an honest report of which credentials are present. It never handles a credential value; the two that remain are printed as ready commands for the owner. The repository was deleted and recreated more than once, and a list that lives in a person's memory is a list that will be wrong one day.
